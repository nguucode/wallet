# Design system: gluestack-ui in Apple's current language (macOS System Settings on web, iOS 27 on app)

History: **web layout rebuilt as macOS System Settings** (sếp, 2026-11-21: "use Apple's current design language exactly; the screenshot is only a reference") on top of the iOS 27 revamp below, which still governs the app layout. Earlier: custom systems ("Clear Ledger", "Violet Sky", "Inset Grouped") → gluestack-ui default theme (2026-11-19) → **iOS / iPadOS 27 revamp on gluestack** (sếp, 2026-11-19, same day). Every screen is still built from **gluestack-ui v4** components; what changed is the values behind the tokens, the type ramp and a few component shapes, so the UI reads as a first-party iPhone/iPad app.

## Sources

- Apple Design Resources lists the **iOS 27 and iPadOS 27** UI kit (Figma, Sketch) and SF Symbols 27; the language is still **Liquid Glass**. WWDC 2026 coverage: iOS 27 refines Liquid Glass for readability (clearer/tinted options, better contrast); iPadOS 27 has edge-to-edge sidebars.
- impeccable's iOS guidance: semantic system colours, one tint, SF Pro, Body 17pt, large titles, inset grouped lists, system materials only behind bars and sheets, 44pt targets, Dark Mode first-class.

## Source of truth

- Components: generated by the gluestack CLI into `src/components/ui/<name>/`, kept as shipped. The one edited file is `gluestack-ui-provider/config.ts` (the colour values).
- Tailwind: `tailwind.config.cjs` (NativeWind preset) holds the type ramp as CSS variables (iOS values as fallbacks), the system font stack, the app tokens (`success`, `backdrop*`, `segment-selected`) and the `mac:` variant (`@media (min-width: 1024px)`, the same breakpoint as `useLayout`).
- `app/globals.css`: the macOS re-valuing of the same tokens and type variables for the web layout, each value tagged with its source.
- Viewer theme: `src/app/theme.ts` writes the tint and backdrop tokens as one stylesheet (`:root` light, `.dark` dark).

## Web layout: macOS System Settings (2026-11-21)

### Provenance

Nothing here is measured from a screenshot of someone's screen or guessed. Every value comes from Apple's own software on macOS 26.6 (25G83), in one of two ways (probe scripts kept out of the repo):

- **[appkit]**: read from AppKit. `NSColor` semantic colours resolved under `aqua` / `darkAqua`, `NSFont.preferredFont(forTextStyle:)`, `NSControl` `fittingSize` per `controlSize`, `NSTableView` `.sourceList` row heights.
- **[render]**: pixels of standard SwiftUI views drawn by the system: `Form` with `.formStyle(.grouped)`, `List(.sidebar)`, `NavigationSplitView`, segmented `Picker`, `.roundedBorder` `TextField`, `Toggle`, `Button` (regular / large / `.borderedProminent`) and `NSAlert`. Each was captured with `screencapture -l` or `cacheDisplay` at 2× and then measured. Windows were inactive, so accent states come from [appkit]. Live windows carry wallpaper tint, so neutral greys come from offscreen renders.
- **[hig]**: Apple Human Interface Guidelines quotes, for behaviour.

### Type

These are [appkit] text styles: Subheadline 11/16, Callout 12/17, Body 13/18 (default), Headline 13 bold, Title 3 15/22, Title 2 17/24, Title 1 22/30, Large Title 26/34. Tailwind `xs` maps to Subheadline, because macOS Footnote is 10pt and too small for Vietnamese. `sm` is Callout, `base` Body, `lg` Title 3, `xl` Title 2, `2xl` Title 1. `3xl`, `4xl` and `5xl` all map to Large Title, since macOS has no larger style, so the balance sets in Large Title.

### Layout and components

- **Window:** the sidebar floats 8pt from the window edge on three sides, is 215pt wide with 18pt corners, and sits on a denser material than the content ([render] NavigationSplitView). The toolbar carries the pane title in Title 3 bold, aligned to the content's leading edge 20pt from the sidebar. Page h1s are screen-reader only on web.
- **Sidebar rows:** 32pt (NSTableView `.sourceList`, medium). The selection is inset 10pt with ~10pt corners and filled with the accent; its label and icon turn white. Icons use the accent colour, per [hig]: "By default, sidebar icons use your app's accent color." Groups are separated by 12pt of space, with no titles (the names stay as screen-reader text).
- **Grouped box (`Card`):** 12pt corners, 20pt from the content edge, 10pt inner inset. Rows are 38pt. Separators stop 10pt short of both box edges.
- **One content edge (2026-11-22, enforced in code):** `INSET` (`src/components/app-ui.tsx`, app 16 / web 10) is the only horizontal edge. `Card inset="content"` pads by it, `inset="rows"` has no padding and its rows (`Row`, `DetailRows`, `SheetList`, custom rows) carry `INSET`; section headers (`Section`, `GroupLabel`) and notes in the column carry it too. Inside a content box the inset drops to 0 (`.content-inset` in `app/globals.css`) and a box inside a box flattens into it, so nesting can never double an edge. Centred content (QR, receipt, amount entry, empty states, grids, charts, rails) is marked `centered` / `data-align="free"`. Blocks are 20pt apart on web (12 between stacked boxes, 30 across a section), 24 on the app. Callers never pad a `Card`, never draw a bordered box by hand, never use gluestack's `Card` directly (guarded by `src/app/ui-contract.test.ts`).
- **UI checker (dev only):** `window.__uiCheckAll({ routes, width, mode })` (`src/dev/uiCheck.ts`) loads every route in a frame and reports: content edge and box edge, gaps off the token set, type sizes off the scale, line height too tight for diacritics, clipped and overlapping text, app targets under 44pt, broken images, console errors, and axe WCAG 2.2 AA. Run it at 1280 and 390, light and dark, before calling UI work done. States beyond a plain route live in `src/dev/uiScenarios.ts`: every flow to its confirm, PIN and result (success, pending, failed), the sheets, menus and dialogs, and onboarding; run `__uiCheckAll({ routes: [...routes, ...__uiScenarios], width, mode })`. The runner presses and types in the frame like a person and restores the viewer's demo data afterwards.
- **gluestack icon slots on web:** `BadgeIcon`, `InputIcon` and `RadioIcon` turn their class into an inline style on web (a console error, and the size and colour never apply). Use `Ico` instead; a radio needs no icon (the indicator draws the filled ring).
- **Menus:** gluestack's menu creator hard-codes `role="list"` over react-aria's `menu`; `src/components/ui/menu` sets `role="menu"` back. A `MenuItem`'s `textValue` is its visible label.
- **App PIN keypad:** a real, labelled control (not hidden from assistive tech while focusable); the dots are a plain view.
- **Step buttons:** a flow step's default button goes through `FlowNext`: on web it joins the footer, trailing, beside Hủy; on the app it is a full-width button under the step.
- **Push buttons:** web secondary buttons carry `.push-button` (white bezel, hairline, soft lift; dark 86/86/90 so the 223 label keeps 5:1).
- **Section header:** Headline (13 bold) in label colour, inset 10pt, 11pt above its box. Boxes are 57.5pt apart across a header.
- **Buttons:** regular push 24pt with 6pt corners. Large is a 28pt capsule. Alert buttons are two equal 28pt capsules, cancel on the left and the action on the right. Flow footers put the default button at the trailing edge.
- **Segmented control:** 24pt track on the bezel fill with 6pt corners. The selected segment is a darker neutral, not the accent.
- **Text field:** 26pt tall with ~10pt corners, filled with the window background ([render] SwiftUI `.roundedBorder`; AppKit's bare `NSTextField` fits in 24pt).
- **Panels (Sheet / Confirm):** NSAlert geometry: 26pt corners, 16pt margins, glass over the popover colour.
- **Popup (filters):** a 24pt pull-down on the bezel fill.
- **Toolbar:** clear over the window at rest; once content scrolls under it, the titlebar material and a hairline. The pane title is Title 3 semibold (probe: `.SFNS-Semibold` 15). Pages and flows put a back button at the toolbar's leading edge, then their title (`src/app/toolbar.ts`; HIG Toolbars). Flows cancel with a "Hủy" button beside the trailing default button, and Return in a field presses the default (HIG Buttons).
- **Content column:** centred, up to 704pt plus 20pt padding (a grouped Form rendered at 1280pt centres 704pt-wide boxes).
- **Value rows (`DetailRows`):** the label is in label colour on the leading side, the value in secondary label on the trailing side, 38pt tall ([render] LabeledContent).
- **Form rows (`Field`, History filters):** the label leads and the control trails. Filters are 24pt pop-up buttons with an up/down chevron (HIG Pop-up buttons).
- **Menus:** 24pt items in 13pt type; the highlighted item is the accent with white text ([appkit] `selectedMenuItemTextColor`).
- **Dialogs:** focus moves in when a dialog opens (an alert's default button, or else the first control). Esc cancels, and focus returns to the control that opened it. Sheets are dismissed with a labelled button at the bottom trailing edge (Hủy for a pending task, Đóng, or Xong for settings), never with a close glyph. The PIN prompt on web is a secure text field; the keypad and dots are app only.
- **Radio buttons:** the selected radio is a filled accent circle with a white centre (HIG Toggles: "a filled circle"); unselected rings use secondary label.
- **Focus ring:** [appkit] `keyboardFocusIndicatorColor` (0 103 244 light, 26 169 255 dark) at 50%, for every focus outline.
- **Unchanged on web:** the balance chart, shortcut discs and recipient rail are Wallet content, not system controls. The balance card is a plain grouped box on web; the dark glow card is app only.

| Token | Light | Dark | Apple role |
|---|---|---|---|
| background | 242 242 247 | 0 0 0 | systemGroupedBackground (web panel, app page) |
| card / popover | 255 255 255 | 28 28 30 | secondarySystemGroupedBackground (cells, sheets) |
| foreground | 0 0 0 | 255 255 255 | label |
| muted-foreground | 100 100 105 | 174 174 178 | secondaryLabel (one step darker than #6C6C70 for AA on the grey) |
| border / input | 198 198 200 / 209 209 214 | 56 56 58 / 72 72 74 | opaque separator / field outline |
| muted, secondary, accent | 233 233 238, 229 229 234 | 44 44 46 | fills (discs, chips, pressed rows) |
| destructive | 215 0 21 | 255 105 97 | systemRed (accessible) = cost / negative |
| success | 28 122 52 | 48 219 91 | systemGreen (darkened for AA) = gained / positive |
| primary | viewer's tint | viewer's tint | tint colour |

**Money meaning** (unchanged): green = money gained / positive (incoming, refunds, balance up, Thành công, Miễn phí, Đã thanh toán, verified, active); red = cost / negative (outgoing, fees, balance down, Không thành công, Quá hạn, over limit); pending, entered and failed (struck) amounts stay neutral. A green or red tint is allowed (sếp asked for the full rainbow); money colours stay `success` / `destructive`, not the tint.

Contrast of every pair above, every tint on every surface, and every backdrop is a unit test (`src/app/theme.test.ts`).

## Type: iOS Dynamic Type defaults (app layout)

System font stack: `-apple-system, BlinkMacSystemFont, "SF Pro Text"`, then Inter (next/font, Vietnamese) elsewhere. gluestack's `Text`/`Heading` sizes resolve through these Tailwind sizes:

| Class | Size / leading | iOS style | Used for |
|---|---|---|---|
| `text-5xl` | 48/52 | display | Home balance |
| `text-4xl` | 34/41 | Large Title | page titles (`Heading 3xl`), transaction amounts |
| `text-xl` | 22/28 | Title 2 | sections (`Heading lg`) |
| `text-lg` | 20/25 | Title 3 | sub-sections (`Heading md`) |
| `text-base` | 17/23 | Body / Headline | body, row titles, menu (23 instead of 22: Vietnamese diacritics) |
| `text-sm` | 15/20 | Subheadline | meta, labels on buttons/chips/tiles, group headings |
| `text-xs` | 13/18 | Footnote | captions, status badges, tab labels, chart axis |

Group headings (`GroupLabel`) are 15 semibold secondary, sentence case; no uppercase on Vietnamese headings.

## Components (in `src/components/app-ui.tsx` unless noted)

- **Card:** inset grouped cell: card surface on the grouped background, `rounded-3xl`, no border or shadow. Lists inside are `divide-y divide-border` rows.
- **Button:** capsule (`rounded-full`); the md size is a 48px filled button (`h-12`); all labels 15px.
- **Badge / StatusPill:** capsules in sentence case (`normal-case`); success outline green, failed solid red (dark text in dark mode), pending outline, refunded neutral.
- **Links:** tint text, no underline.
- **Sheet:** Actionsheet with 32px top corners on app, Modal with 24px corners on web, both on the card surface.
- **Sheets (app):** a 44pt close glyph at the leading edge and a centred inline title (HIG Sheets puts dismissal on the leading edge; HIG Toolbars says to use a glyph, not a "Close" label).
- **Tab bar (app):** Quét mã is an ordinary tab: HIG Tab bars, "not to provide actions". The large title is the section's name, never the app name (HIG Toolbars).
- **Layout breakpoint:** the app layout covers everything under 1024px, iPad portrait included (product decision). It is judged as iPhone; there is no iPadOS-specific layout.
- **NavBar (app):** clear at rest; glass material (`bg-backdrop-app/75 backdrop-blur-xl` + hairline) once content scrolls under it; large title below on tab roots.
- **Tab bar (app, `Shell.tsx`):** floating Liquid Glass capsule above the home indicator (`bg-card/75 backdrop-blur-2xl`, hairline, soft shadow); current tab is a tinted pill; Scan stays the filled tint button.
- **Web shell, cards, buttons, sheets on web:** see "Web layout: macOS System Settings" above (the `mac:` classes in these components).
- **Balance card (`HomePage.tsx`), app layout:** dark in both modes: the card is a `dark` scope, so every token inside takes its dark value (text, chart, chip, tint); a radial glow of the tint sits on its own layer behind the content. On web it is a plain grouped box.
- Materials (blur) only on bars, the tab bar, the sidebar and panels: never behind reading content.

## Viewer theme (Demo controls)

Laid out as macOS System Settings > Appearance (2026-11-22): grouped boxes, the label leading and every choice visible trailing, the chosen one with a 2pt accent ring and its name in semibold. The sheet holds only this theme block and the sample PIN line (scenario, outcome, event and clock controls removed 2026-11-22). Push buttons on web carry a white bezel with a hairline and a soft lift (dark: a raised grey) so they read on glass. The web sheet body scrolls.

- **Giao diện:** Theo hệ thống / Sáng / Tối, shown as small window pictures (System is half light, half dark). Tailwind `darkMode: 'class'`; gluestack's colour-mode script, inlined in `<head>` with the stored mode.
- **Kính (web only):** Vibrancy (pre-Tahoe `NSVisualEffectView`: tint 60–80% over `blur(30px) saturate(180%)`) or Liquid Glass (tint 35–60%, `blur(14px) saturate(200%)`, a lit rim). Applied to `.material-sidebar`, `-titlebar`, `-menu` and `-sheet` through `html[data-glass]` in `app/globals.css`. There is no refraction: `url()` in `backdrop-filter` is Chromium-only. Reduce Transparency turns both solid.
- **Màu chủ đạo:** the seven rainbow colours (Đỏ, Cam, Vàng, Lục, Lam, Chàm, Tím) as Apple's accessible system colours; default Lam (iOS blue). The chosen colour's name sits under its swatch.
- **Nền:** Hình nền (default), Xám trung tính, Chuyển màu. Hình nền is a desktop-style colour field of our own (no Apple artwork): warm stops on the left behind the sidebar, cool ones on the right. The whole window (web) or page (app) shows it through one even veil (84% light, 82% dark), as macOS's "Tint window background with wallpaper colour" does, and the sidebar's glass floats on that. A bare-wallpaper column behind the sidebar was tried and dropped: it split the window in two. The veil is tested so label text keeps 7:1 and secondary text and links keep AA over every wallpaper colour. Chuyển màu tints stop at 8% mixed into white (AA, tested). Group boxes are white on the window.
- Web: the palette button in the sidebar footer opens the Demo controls sheet; app: top of the Demo controls sheet. Stored per viewer in localStorage; "Mặc định" (in the Chủ đề header) restores Lam / system / Hình nền / Vibrancy.

## Conventions kept from the gluestack audits

- Headings always pass `as` (h1 page title, h2 section, h3 sub-section); never `as` with `isTruncated` (use `truncate`).
- Notes and info boxes: Alert surface (`rounded-lg border border-border bg-card p-4`); never secondary text on a fill.
- Icons inside buttons through `Ico`, not `ButtonIcon`.
- Row actions: a Sheet on both layouts (gluestack's Menu popover cannot shift off the right edge).
- Providers: `GluestackUIProvider` in `app/layout.tsx` (SSR theme variables) and again inside `BrowserRouter` (overlays need router context).
- Web content scrolls in `#main-scroll`: use `pageScroller()`, never `window.scrollY`.
- One literal colour: `bg-white` behind QR codes and barcodes (scanning).

## Rules

1. No raw HTML elements for UI in screens: gluestack components only. An `<svg>` drawing (QR, barcode, chart) is the exception.
2. Colours only through tokens; no hex in screens. Glass/blur only where listed above.
3. Accessibility: one h1 per page, flows included (focused on route change; screen-reader only on web, where the toolbar shows it), live regions for status and errors, labelled inputs, skip link, 44pt targets on the app layout, AA contrast in light and dark (unit-tested on the iOS tokens; axe on web routes, 2026-11-21: 16 routes × light/dark plus 5 app routes clean after three Apple-conformance review rounds).
